# نشر قاعدة بيانات دائمة

الموقع يعمل بواجهة عربية متعددة الصفحات، وخادم Flask، وقاعدة SQLite على الخادم. تتضمن الصفحات كتالوج القطع في `index.html`، وشرح مكونات الجهاز الكامل في `components.html`، ودليل اللوحات الأم في `motherboards.html`، وصفحة الميزانيات في `budgets.html` التي تعرض تسع خطط بحسب سقف السعر وستة أنواع استخدام. لا تفتح `index.html` مباشرة عند استخدام قاعدة البيانات؛ شغّل الخادم وافتح عنوانه حتى تتصل الواجهة بالـ API.

## تشغيل محلي

يتطلب Python 3.10 أو أحدث.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:ADMIN_SETUP_TOKEN = 'ضع-هنا-رمز-إعداد-طويل-وعشوائي'
$env:DATABASE_PATH = 'data/memar.sqlite3'
python server.py
```

افتح `http://localhost:8000`. أنشئ الحساب الأول باسم `iyr3` وأدخل الرمز الموجود في `ADMIN_SETUP_TOKEN`. هذا الحساب هو مالك الموقع، وهو وحده يستطيع تعيين حسابات أخرى كمديرين أو إزالة صلاحياتهم. التسجيلات اللاحقة تبدأ كمستخدمين عاديين. لا تضع الرمز داخل ملفات الموقع أو ترفعه إلى Git.

## النشر على Render

1. أنشئ خدمة Web Service من هذا المجلد، واضبط Build Command على `pip install -r requirements.txt`.
2. اضبط Start Command على `waitress-serve --listen=0.0.0.0:$PORT server:app`.
3. أضف قرصًا دائمًا للخدمة، مثل نقطة تركيب `/var/data`، واضبط متغير البيئة `DATABASE_PATH=/var/data/memar.sqlite3`.
4. أضف `ADMIN_SETUP_TOKEN` كمتغير سري طويل وعشوائي في إعدادات الخدمة.
5. افتح رابط الموقع، ثم أنشئ حساب `iyr3` باستخدام رمز الإعداد. بعد إنشاء المالك لن يقبل الخادم الرمز لإنشاء مالك آخر، وتظل إدارة أدوار الحسابات حصرية لـ `iyr3`.

على أي استضافة أخرى، استخدم نفس المبدأ: شغّل `server:app` عبر Waitress، واجعل `DATABASE_PATH` داخل قرص دائم تحتفظ به الاستضافة بين عمليات النشر وإعادة التشغيل. لا تحفظ قاعدة البيانات داخل مجلد مؤقت أو مجلد بناء.

## النسخ الاحتياطي والاستعادة

من حساب `iyr3` افتح «لوحة المدير»، ثم استخدم «تنزيل نسخة كاملة» أو «استعادة نسخة». النسخة JSON تشمل قطع الدليل والحسابات وتجزئات كلمات المرور، ولا تشمل جلسات الدخول. ملف النسخة حساس؛ خزّنه في مكان خاص. الاستعادة تستبدل بيانات الموقع الحالية وتسجّل خروج المستخدمين.

لنسخة إضافية مستقلة عن الموقع، نزّل النسخة الاحتياطية واحتفظ بها خارج مجلد الاستضافة. تنزيل الملف لا يغني عن القرص الدائم؛ القرص الدائم يحفظ البيانات تلقائيًا بعد إعادة تشغيل الخدمة.

## ملاحظات تقنية

- تعرض واجهة القطع بيانات القراءة للعامة، بينما الإضافة والتعديل والحذف والاستعادة تتطلب جلسة مدير على الخادم.
- الحسابات والصلاحيات والجلسات محفوظة في SQLite. ملفات الجلسة تستخدم Cookie من نوع HttpOnly وSameSite=Lax. المديرون الآخرون يستطيعون إدارة القطع، بينما إدارة الحسابات والنسخ الكاملة حصرية لـ `iyr3`.
- بيانات المتصفح القديمة لا تُرفع تلقائيًا. نزّل نسخة منها من الصفحة المحلية ثم استوردها بعد تشغيل الموقع على الخادم.
- ميزانيات التجميعات بالجنيه المصري تقديرية وليست أسعارًا لحظية؛ راجع السوق والضمان والتوافر قبل الشراء.
- SQLite مناسبة لموقع صغير بخدمة واحدة وقرص دائم. للمواقع ذات عدة نسخ تشغيل أو حركة عالية، استخدم PostgreSQL بدلًا منها.
